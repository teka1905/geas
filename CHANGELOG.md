## 0.5.1 — 2026-10-07

### Исправлено

- **`type: number` в d42 принимает целые.** Раньше `number` переводился в
  `schema.float`, и валидный ответ с целым значением (`{"value": 7}`) падал и на
  generated d42-схеме, и в `validate_response`. Теперь `number` — это
  `schema.any(schema.float, json_int)`. Границы действуют на обе ветки (у целой —
  округлённые внутрь), `enum` сравнивается по значению (`1` и `1.0` — одно
  значение). `bool` не принимается. `json_int` и `JsonIntSchema` экспортируются из
  `geas.integrations.d42`. `integer` и JSON Schema контракта не меняются.
  Подробности — в разделе
  [`number` в d42](docs/support-matrix.md#number-в-d42).
- **Waiver внутри варианта с `discriminator.mapping`.** Waiver на пути через
  вариант `oneOf` (`/body/payload/#1/tickets/variableId`) разворачивает вариант
  по месту, и раньше генерация падала: «`discriminator.mapping['TICKET_REF']` …
  нет среди вариантов». Теперь `mapping` сопоставляется с вариантами по индексу.
  В `if`/`then` для развёрнутого варианта подставляется его схема с послаблением.
  Ссылка на исходное определение обошла бы waiver. У вариантов-ссылок JSON
  Schema контракта не меняется. `Discriminator.mapping` в IR теперь хранит
  индекс варианта вместо имени определения.

### Изменено

- **Generated d42-схемы `number` меняют форму:** `schema.float...` →
  `schema.any(schema.float..., json_int...)`. После обновления перегенерируйте
  артефакты (`geas update`), иначе `geas check` упадёт на расхождении.
  - `%` и `fake()` работают как раньше.
  - `build_fixture` по-прежнему даёт дробное значение, поэтому закоммиченные
    фикстуры не меняются.
  - Overlay с ручной `schema.float` на таком поле работает, а с `schema.int` —
    теперь тоже.
  - Ломается только код, который разбирает generated-схему `number` как
    `FloatSchema` (`.props.min`, сравнение с `schema.float...`).

## 0.5.0 — 2026-09-28

d42 для рекурсивных контрактов и полиморфных DTO. Цикл больше не выключает d42
для операции целиком: он отсекается там, где замыкается, а отсечённый узел
проверяется по JSON Schema контракта. `allOf` (в том числе springdoc-DTO с
`properties` + `oneOf` + `discriminator`) больше не выключает d42: пересечение
распределяется по вариантам объединения. Решения и альтернативы —
[ADR 0003](docs/adr/0003-recursive-d42-cycle-cut.md) и
[ADR 0004](docs/adr/0004-polymorphic-all-of-d42.md).

### Добавлено

- **d42 для `allOf`.** `allOf(база, oneOf(V1, ..., Vn))` переводится в
  `schema.any(база ∧ V1, ..., база ∧ Vn)`, где `∧` — пересечение узлов контракта
  (`geas.integrations.d42.intersection`). Перевод не уже контракта; шире он только
  в эксклюзивности `oneOf`, которую по-прежнему держит JSON Schema. `discriminator`
  сужает ветки: его свойство обязательно, а из `enum` ветки варианта исключаются
  значения, которые `mapping` отдаёт другим вариантам, поэтому `fake()` не
  собирает ветку одного варианта с меткой другого (у строки без `enum` исключение
  не выражается). Ветка, равная своему варианту, остаётся ссылкой на его generated-схему,
  `allOf: [$ref база]` без своих ограничений становится алиасом базы. Рекурсия
  через вариант отсекается общим механизмом. JSON Schema контракта не меняется.
- `geas update` печатает ветку `allOf`, которая по контракту не допускает ни
  одного значения и выброшена из d42 (`ветка Puid в allOf
  SamsaraClientIdentifierDto:/ выброшена из d42 — ...`): это почти наверняка
  ошибка спецификации. Те же данные — `ArtifactSet.d42_dropped_branches`.
- `module_notes(...)` в `geas.integrations.d42.renderer` — отсечки циклов и
  выброшенные ветки модуля одним проходом; `cycle_cuts(...)` сохранён.
- **Отсечка цикла в d42.** Граф определений обходится от тел запроса и ответа;
  ссылка, которая возвращает обход в определение с текущего пути, становится
  узлом `RecursiveRefSchema`. Всё до него — обычная generated-схема. Узел
  проверяет значение по JSON Schema определения на любой глубине (без `format`,
  как и весь d42-путь), `%` делегирует типизированной схеме того же определения —
  частичная подстановка уходит внутрь дерева, — а `fake()` и `build_fixture`
  дают минимальный экземпляр, сверенный с JSON Schema. Если у определения нет
  конечного значения, поднимается `RecursiveSchemaError`, если минимальный
  экземпляр нарушает контракт — `ValidationFailedError`; обе ошибки советуют `%`.
  Overlay'и работают в типизированной части, путь в рекурсивную часть —
  `ContractOverlayError` с той же подсказкой. JSON Schema отсечённых
  определений встраивается в d42-модуль (`_RECURSION = RecursionContract(...)`).
- `geas update` печатает место каждой отсечки: `операция (направление): цикл
  отсечён на ссылке A -> B`.
- `render_module(..., roots=...)` и `cycle_cuts(...)` в
  `geas.integrations.d42.renderer`, `RecursionContract` и `RecursiveRefSchema`
  в `geas.integrations.d42`.

### Изменено

- **Направления d42 независимы.** Невыразимая в d42 конструкция (`multipleOf`,
  `pattern` с границами длины, недоказуемый `allOf`) выключает d42 только в том
  направлении, где встретилась: запрос не теряет d42-схемы из-за ответа и
  наоборот. В документе контракта — `d42.<direction>_module: null` и
  `d42.<direction>_reason`; сводная `d42.reason` сохранена.
- `d42.recursive` в документе контракта стал справочным: рекурсия d42 не
  отключает.
- **Причины отказа d42 для `allOf` стали конкретными.** Вместо «allOf не
  выражается в d42: у языка нет пересечения типов» — `allOf не выражается в d42:
  пересечение ветки <вариант> не доказуемо — <причина> [contract path
  <определение>:/<свойство>]` (два разных `pattern`, `integer` против `number`,
  ключ, который в открытом объекте обязан отсутствовать, `allOf`, ссылающийся сам
  на себя) либо `allOf не допускает ни одного значения: <причина>`.
- Нижняя граница extra `[d42]` — `d42>=2.3,<3`: интеграция опирается на
  `optional.absent` (`d42.declaration.types.is_absent`), которого нет в d42 2.2.
- **Отпечаток `replace_schema` на `$ref`-точке считается по цели ссылки.** Раньше
  waiver на свойство вида `{$ref: JsonNode}` закреплял только текст ссылки и не
  замечал, что бэкенд переписал `JsonNode`. Теперь отпечаток — тот же, что у
  `allow_null`, `extend_enum` и `ignore_discriminator` на этой точке: по цели с
  наложенными соседями `$ref`. **Миграция:** выписанный ранее `replace_schema` на
  `$ref`-точке после обновления ломает генерацию с «waiver … устарел»; перенесите
  значение `фактический` в `expected_source`. На inline-точках отпечаток не
  изменился.

### Исправлено

- **`pattern`, который Python `re` не разбирает, отклоняется при генерации.**
  Паттерн в синтаксисе ECMA/Java вроде `^\p{Lu}+$` раньше проходил `geas update`
  (а рядом с `enum` ронял его сырым `re.error`), после чего `validate_*` и моки
  падали `re.error` уже в тестах: JSON Schema контракта проверяется на Python `re`.
  Теперь это `UnsupportedConstructError` с contract path и готовым waiver'ом
  `allow_any`; паттерн можно и переписать (`[A-Z]` вместо `\p{Lu}`).
- **`required` без схемы больше не теряется.** Ключ, который `required` называет,
  а `properties` той же схемы нет, раньше молча выпадал из контракта, если
  `properties` пуст: у наследника в стиле springdoc
  (`{type: object, required: [argList, type], allOf: [...]}`) `argList` был
  необязателен и в JSON Schema, и в d42. Теперь ключ обязателен: JSON Schema
  получает его в `required`, d42 — обязательный ключ (схему даёт пересечение с
  другой частью `allOf`, в одиночном объекте значение любое), `describe()`
  показывает его. Рядом с композицией такой ключ допустим и при непустом
  `properties` (раньше — отказ); в одиночном объекте с непустым `properties` он
  по-прежнему отклоняется как опечатка, при `additionalProperties: false` — как
  пустой контракт. `relax_required` и `add_property` работают на нём тем же путём,
  что на свойстве. Требование ключа, который направление вырезало у другой части
  `allOf` (`readOnly` в запросе, `writeOnly` в ответе), действует только в другом
  направлении, как и внутри одного объекта: наследник
  `{required: [id, name], allOf: [$ref Base]}` с `readOnly` `id` не требует `id` в
  запросе. Контракты затронутых операций меняются — это исправление.
- **Ложное «установите geas[d42]» на старой d42.** С d42 2.2 импорт интеграции
  падал сырым `ImportError`, а `geas update` и `geas add` переупаковывали его в
  «требует опциональной зависимости». Теперь `MissingExtraError` называет
  установленную версию и требование `d42>=2.3,<3`.
- **`allow_null`, `extend_enum` и `ignore_discriminator` работают на `$ref`-точке.**
  Раньше waiver на свойство вида `{$ref: JsonNode}` сверялся дважды — с узлом
  `$ref` и с развёрнутой целью, — и отпечатки у них разные: `allow_null` требовал
  то один `expected_source`, то другой и не сходился никогда, а `extend_enum` и
  `ignore_discriminator` падали с «enum/discriminator отсутствует», потому что
  патчили узел `$ref`. Теперь эти правила действуют на цель ссылки с наложенными
  соседями (`readOnly`, nullable-маркер) и сверяются с ней один раз. Отпечаток —
  тот же, что у такого же фрагмента inline, и меняется при правке цели.

## 0.4.0 — 2026-09-23

### Добавлено

- **`relax_required` для параметров.** Waiver с `json_pointer:
  /param/query/<name>` или `/param/header/<name>` снимает ошибочный
  `required: true` с query-параметра или заголовка — раньше правило работало
  только для свойств объекта, и параметр, который клиент законно не передаёт,
  нельзя было ослабить ничем. Реальный случай: `skipDuplicatesCheck` у
  `addArticle` объявлен обязательным, а фронтенд его не шлёт, и `ContractMock`
  отклонял каждый запрос. Отпечаток считается по схеме параметра; после
  исправления спецификации waiver перестаёт применяться и ломает генерацию, как
  и остальные. Path-параметры не ослабляются.

### Изменено

- **Сужение waiver'а, которое не может сработать, отвергается при загрузке.**
  `status` и `content_type` у waiver'а с `direction: request`, а также
  `content_type` у waiver'а на заголовок ответа (`/param/header/<name>`) ни с чем
  не совпадали: генерация падала с невнятным «waiver'ы больше не нужны». Теперь
  `waivers.yaml` не загружается, а ошибка называет запись и причину. Рабочие
  файлы это не ломает: такие waiver'ы и раньше роняли генерацию.

### Исправлено

- **Повторяющийся `operationId` в режиме `explicit`.** Если генератор
  спецификации выпускал один `operationId` на нескольких ручках, падала любая
  запись manifest с этим `operation_id`, даже когда `method` и `path` были
  закреплены. `geas add` с `--method` и `--path`, которые он сам же и
  предлагал, тоже не проходил. Теперь операция выбирается по закреплённому
  маршруту; без `method` и `path` это по-прежнему ошибка со списком
  маршрутов, а если закреплённого маршрута среди них нет, ошибка называет и его.
- **`geas list` отмечал выбранные операции только по `operationId`.** При дубле
  звёздочку и ключ получали все ручки с этим `operationId`, а операция,
  привязанная по `method` + `path` без `operationId`, не отмечалась вовсе.
  Отметка теперь ставится по тем же правилам, что и привязка.
- **Короткая форма пути `non_waivable` (`/id` вместо `/body/id`).** Она
  принималась, но waiver на ту же точку не отвергался при загрузке и падал
  только тогда, когда действительно нарушал правило. Теперь обе формы
  защищают точку одинаково, а в ошибке печатается полный путь.
- **`OperationHandle.d42_schema()` без `export`.** У параметра было значение по
  умолчанию, но вызов без него всегда падал с ложным «d42-схемы не
  сгенерированы: контракт рекурсивен либо `d42: false`». Теперь единственная
  d42-схема направления возвращается сама, как это делают `response()` и
  `request.body()`. Если схем несколько, ошибка просит `export` и перечисляет
  варианты.
- Ошибка для OpenAPI 3.1 больше не ссылается на устаревшую «версию 0.1».

## 0.3.0 — 2026-09-10

Область действия waiver'а и предупреждение об истечении. Один дефект корневой
модели больше не требует по записи на каждый лист, а дата истечения перестала
быть обрывом без предупреждения.

### Добавлено

- **`scope: exact | subtree` у waiver'а.** `scope: subtree` закрепляет
  послабление за узлом и всем поддеревом под ним. Реальный случай, ради которого
  это сделано: генератор Swagger 2 пометил всю request-модель операции как
  `readOnly`, и один дефект требовал 75 одинаковых записей. Теперь это одна
  запись, дающая **побайтово тот же** контракт. По умолчанию — `exact`;
  в канонический вид файла `exact` не пишется, поэтому проекты без поддеревьев
  не получают диффа.
- **Ограничение по правилам.** `subtree` допускают только `ignore_read_only`,
  `ignore_write_only` и `relax_required` — те, что решают судьбу *слота*
  свойства, а не его содержимого. `replace_schema`, `add_property`,
  `extend_enum`, `allow_any` и остальные отвергаются при загрузке с объяснением
  причины.
- **Отпечаток по всему поддереву.** `expected_source` subtree-waiver'а считается
  по поддереву с развёрнутыми `$ref`: правка типа, `enum`, `required` или состава
  свойств где угодно внутри ломает генерацию явно. Отпечаток не зависит от
  порядка ключей, от правки `description`/`example` и от того, вынесен ли
  фрагмент в `$ref` или написан по месту.
- **Покрытие в отчёте.** `geas update` и `geas check` печатают, сколько точек
  контракта накрыл каждый subtree-waiver, — это то, по чему на ревью видно, не
  слишком ли запись широка. Для `assert_all_used()` достаточно одного
  срабатывания.
- **`policies.waiver_warn_days` (по умолчанию 14).** `geas check` и `geas update`
  печатают в stderr предупреждение по waiver'ам, истекающим в этом окне, и **не**
  роняют сборку. Окно шире `waiver_max_days` отвергается как ошибка конфигурации.
- **`geas.normalization.refs.expand_refs`** — развёртка `$ref` в самодостаточное
  дерево с маркером цикла вместо бесконечной рекурсии.

### Изменено

- Диагностика устаревшего waiver'а и пересечения с `non_waivable` печатает обе
  координаты: и покрывающий waiver, и конкретную точку контракта, на которой
  разошлось.
- `$ref` внутри заявленного поддерева разворачивается по месту — так же, как это
  давно делается на пути точечного waiver'а. Без этого послабление досталось бы
  соседним операциям, ссылающимся на ту же именованную схему. Рекурсия внутри
  поддерева стала явной ошибкой с предложением сузить `scope`.
- `policies` в каноническом виде manifest содержит `waiver_warn_days`.
- Версия генератора в `_generated.json` изменилась на `0.3.0`: у потребителя
  обновление пина и перегенерация артефактов идут одной пачкой.

### Совместимость

`waivers.yaml` без `scope` работает ровно как раньше, включая канонический вид
файла: 0.3.0 обратно совместима с 0.2.0. Решения и их обоснование —
[ADR 0002](docs/adr/0002-waiver-subtree-scope.md).

## 0.2.0 — 2026-09-09

Навигация по сгенерированному контракту: от alias-файла в проекте до
generated JSON Schema и d42-схемы — один шаг, а не поиск по каталогу.

### Добавлено

- **Координаты артефактов у выбранного варианта.** `RequestBodyView` и
  `ResponseView` знают `contract_file`, `json_pointer` (RFC 6901),
  `contract_path`, `d42_module`, `d42_export`, `d42_reference` и
  `d42_source_path`. Путь к исходнику generated d42-схемы вычисляется по
  раскладке артефактов **без импорта** модуля, поэтому просмотр контракта
  работает и без extra `[d42]`. Если своей generated-схемы у варианта нет,
  d42-координаты равны `None`: путь к схеме соседнего варианта не подставляется.
- **`view.describe()`, `operation.describe_response()` и
  `operation.describe_request_body()`** — человекочитаемая форма контракта:
  поля, `required`/`optional`, типы, `enum`, `const`, nullable, комбинаторы,
  строковые и числовые ограничения, параметры массивов, политика
  `additionalProperties`, а в конце — точные адреса JSON Schema и d42. Методы
  возвращают строку и ничего не печатают.
- **Модуль `geas.runtime.description`** — обход и форматирование JSON Schema
  отдельно от `OperationHandle`. Локальные `$ref` (`#/$defs/…`,
  `#/definitions/…`) раскрываются, внешние только называются: описание не ходит
  ни в сеть, ни на диск. Рекурсия и вложенность глубже `max_depth` обрываются
  явным маркером. Неизвестное ключевое слово перечисляется по имени и **не**
  превращается в «любое значение».
- **Команда `geas show OPERATION [--direction] [--status] [--content-type]
  [--json] [--max-depth]`.** Читает только готовые артефакты: ничего не
  перегенерирует, не открывает upstream OpenAPI, не требует d42. Единственный
  вариант выбирается автоматически, неоднозначность даёт код `2` со списком
  допустимых значений, отсутствие артефактов — код `1` с подсказкой запустить
  `geas update`. `--json` печатает валидный JSON с координатами артефактов и
  самой схемой.

### Изменено

- `handle_from_document()` принимает необязательные `contract_file` и
  `d42_dir`. Без них поведение прежнее — у views просто нет координат.
- Границы, дословно повторяющие диапазон `format: int32`/`int64`, в описании не
  дублируются: печатается сам `format`. Ни контракт, ни generated JSON Schema
  это не меняет.

Существующее поведение сохранено: `operations.*`, `response()`, `d42_schema()`,
`mock()`, формат документа контракта (`artifact.version: 1`) и формат
generated-набора (`artifact_format: 1`) прежние. Единственное изменение в
артефактах — поле `generator` в `_generated.json`, поэтому после обновления
библиотеки потребителю нужен один `geas update`.

## 0.1.0 — 2026-09-08

Первый срез проекта: генерация тестовых контрактов, схем и моков из
checked-in OpenAPI-спецификаций.

### Добавлено

- **Имя Geas** для distribution, Python-пакета и CLI. Оно обозначает
  обязательное условие, нарушение которого имеет последствия — ту же роль
  выполняет исполняемый OpenAPI-контракт.
- **Нормализация Swagger 2.0 и OpenAPI 3.0.x** в одно внутреннее
  представление: диалект спецификации распознаётся явно, а различия версий
  (`definitions` против `components`, `nullable`, form-параметры, `produces`
  и `consumes`) сводятся к общей модели ещё до генерации артефактов.
- **Fail-closed диагностика.** Неподдержанная конструкция, неизвестный
  `format`, рекурсивная схема, битый `$ref`, выход `$ref` за корень источника
  и расхождение с зафиксированной привязкой операции останавливают генерацию с
  точной ошибкой и адресом внутри контракта. Контракт никогда не «ослабляется
  молча» до «любого значения».
- **Generated JSON Schema** для тела запроса, тела ответа и параметров каждой
  выбранной операции — детерминированная отрисовка с сортированными ключами,
  пригодная для валидации без установленных extras.
- **Generated d42-схемы** — параллельное представление того же контракта для
  генерации тестовых данных и утверждений в тестах.
- **Generator overlays** — точечные, версионируемые правки поверх
  сгенерированного слоя, позволяющие уточнить контракт (например, сузить тип
  или закрепить пример), не редактируя generated-файлы руками и не теряя
  правки при следующей генерации.
- **Generated operation namespace** — импортируемое дерево модулей, где каждая
  операция доступна по стабильному пути; коллизии имён определяются на этапе
  разбора manifest и требуют явного `python_path`.
- **Operation-aware JJ-моки** — моки, знающие метод, маршрут и выбранный
  вариант ответа операции, поэтому подставляемое тело проверяется тем же
  контрактом, что и настоящий ответ сервиса.
- **Waivers** — единственный способ пропустить конструкцию, которую
  нормализация иначе отклонила бы. Waiver требует владельца, причины, тикета и
  срока, действует ровно для одной пары «операция + направление» и одного
  адреса внутри контракта, закрепляет исходный фрагмент схемы и ломает
  генерацию, когда просрочен, не использован, избыточен или устарел.
- **CLI `geas`** с командами `init` (каркас manifest и waivers),
  `list` (операции источника), `add` и `update` (добавление и перегенерация
  выбранных операций), `check` (проверка, что закоммиченные артефакты
  совпадают с генерацией) и `diff` (человекочитаемое расхождение контракта).
- **Точный d42-тип для `additionalProperties: <schema>`**, совместимый с
  `fake()`, `%`, `make_required()` и generator overlays.
- **Waiver'ы для дефектных generated-моделей запросов**: direction-маркеры,
  nullable, discriminator, неполный enum и отсутствующие свойства.
- **Реальные диапазоны `int32`/`int64`** в JSON Schema и d42 вместо
  декоративного `format` без проверки границ.
- **Безопасный dependency extra `jsonschema[format-nongpl]`** и модульная точка
  входа `python -m geas`.
- **Совместимая с JJ история в виде `list`** и необязательный
  `history_callback` для интеграции с отчётами потребителя без зависимости от
  конкретного test framework.
- **Полный binding в `add`**: CLI автоматически закрепляет method, полный path,
  единственные request/response media types и generated Python path; при
  неоднозначности требует явный селектор вместо неполной записи в manifest.

### Ограничения

- **OpenAPI 3.1 не поддерживается.** Спецификация версии 3.1 не обрабатывается
  «как получится»: диалект распознаётся и отклоняется явной диагностикой,
  потому что модель типов там иная (`type` как список, полноценный
  JSON Schema 2020-12, `const`, `examples`) и молчаливое приведение к 3.0
  исказило бы контракт.
- **Нет decorator API.** В версии 0.1 контракт подключается явным импортом из
  generated-пространства имён; декораторы для тестовых функций сознательно
  отложены, чтобы не фиксировать интерфейс до появления практики применения.
