# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),

## 0.1.0 — 2026-09-08

Первый срез проекта: генерация тестовых контрактов, схем и моков из
checked-in OpenAPI-спецификаций.

### Добавлено

- **Имя Geas** для distribution, Python-пакета и CLI. Оно обозначает
  обязательное условие, нарушение которого имеет последствия — ту же роль
  выполняет исполняемый OpenAPI-контракт.
- **Нормализация Swagger 2.0 и OpenAPI 3.0.x** в одно внутреннее
  представление: диалект спецификации распознаётся явно, а различия версий
  (`definitions` против `components`, `nullable`, form-параметры, `produces`
  и `consumes`) сводятся к общей модели ещё до генерации артефактов.
- **Fail-closed диагностика.** Неподдержанная конструкция, неизвестный
  `format`, рекурсивная схема, битый `$ref`, выход `$ref` за корень источника
  и расхождение с зафиксированной привязкой операции останавливают генерацию с
  точной ошибкой и адресом внутри контракта. Контракт никогда не «ослабляется
  молча» до «любого значения».
- **Generated JSON Schema** для тела запроса, тела ответа и параметров каждой
  выбранной операции — детерминированная отрисовка с сортированными ключами,
  пригодная для валидации без установленных extras.
- **Generated d42-схемы** — параллельное представление того же контракта для
  генерации тестовых данных и утверждений в тестах.
- **Generator overlays** — точечные, версионируемые правки поверх
  сгенерированного слоя, позволяющие уточнить контракт (например, сузить тип
  или закрепить пример), не редактируя generated-файлы руками и не теряя
  правки при следующей генерации.
- **Generated operation namespace** — импортируемое дерево модулей, где каждая
  операция доступна по стабильному пути; коллизии имён определяются на этапе
  разбора manifest и требуют явного `python_path`.
- **Operation-aware JJ-моки** — моки, знающие метод, маршрут и выбранный
  вариант ответа операции, поэтому подставляемое тело проверяется тем же
  контрактом, что и настоящий ответ сервиса.
- **Waivers** — единственный способ пропустить конструкцию, которую
  нормализация иначе отклонила бы. Waiver требует владельца, причины, тикета и
  срока, действует ровно для одной пары «операция + направление» и одного
  адреса внутри контракта, закрепляет исходный фрагмент схемы и ломает
  генерацию, когда просрочен, не использован, избыточен или устарел.
- **CLI `geas`** с командами `init` (каркас manifest и waivers),
  `list` (операции источника), `add` и `update` (добавление и перегенерация
  выбранных операций), `check` (проверка, что закоммиченные артефакты
  совпадают с генерацией) и `diff` (человекочитаемое расхождение контракта).
- **Точный d42-тип для `additionalProperties: <schema>`**, совместимый с
  `fake()`, `%`, `make_required()` и generator overlays.
- **Waiver'ы для дефектных generated-моделей запросов**: direction-маркеры,
  nullable, discriminator, неполный enum и отсутствующие свойства.
- **Реальные диапазоны `int32`/`int64`** в JSON Schema и d42 вместо
  декоративного `format` без проверки границ.
- **Безопасный dependency extra `jsonschema[format-nongpl]`** и модульная точка
  входа `python -m geas`.
- **Совместимая с JJ история в виде `list`** и необязательный
  `history_callback` для интеграции с отчётами потребителя без зависимости от
  конкретного test framework.
- **Полный binding в `add`**: CLI автоматически закрепляет method, полный path,
  единственные request/response media types и generated Python path; при
  неоднозначности требует явный селектор вместо неполной записи в manifest.

### Ограничения

- **OpenAPI 3.1 не поддерживается.** Спецификация версии 3.1 не обрабатывается
  «как получится»: диалект распознаётся и отклоняется явной диагностикой,
  потому что модель типов там иная (`type` как список, полноценный
  JSON Schema 2020-12, `const`, `examples`) и молчаливое приведение к 3.0
  исказило бы контракт.
- **Нет decorator API.** В версии 0.1 контракт подключается явным импортом из
  generated-пространства имён; декораторы для тестовых функций сознательно
  отложены, чтобы не фиксировать интерфейс до появления практики применения.
