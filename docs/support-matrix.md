# Матрица поддержки OpenAPI 3.0.x и Swagger 2.0

Справочник: какие конструкции спецификации geas переносит в контракт и что
происходит с остальными.

Каждая конструкция находится в одном из трёх состояний:

- **поддержано** — переносится в контракт точно;
- **аннотация** — распознаётся и отбрасывается, на контракт не влияет;
- **отклоняется** — генерация падает с сообщением, в котором есть JSON Pointer
  в спецификации и contract path.

Частичной или приблизительной поддержки нет: если geas не может перенести
конструкцию точно, генерация падает.

**Если конструкция отклонена**, исправьте спецификацию. Если это невозможно,
выпишите waiver по заготовке из сообщения об ошибке, см.
[waivers.md](waivers.md#как-выписать-waiver).

## Версии документов

| Версия | Поведение |
| --- | --- |
| `swagger: "2.0"` | поддержано |
| `openapi: 3.0.x` | поддержано |
| `openapi: 3.1.x` | **отклоняется** с объяснением несовместимости |
| `swagger: "1.x"`, другие версии `openapi` | отклоняется |
| документ без `swagger` и `openapi` | отклоняется |

OpenAPI 3.1 не является надмножеством 3.0: в нём нет `nullable`,
`exclusiveMinimum`/`exclusiveMaximum` стали числовыми, `type` может быть
массивом. Если разбирать 3.1 по правилам 3.0, контракт исказится без
предупреждения, поэтому такой документ отклоняется целиком.

### `oneOf` в d42

В d42-проекции `oneOf` становится `schema.any(...)`: значение, подходящее сразу
под две ветки, d42 пропустит. Точная семантика `oneOf` и `discriminator`
сохраняется в JSON Schema. Моки и `validate_*` всегда проверяют тело по JSON
Schema, и отключить эту проверку нельзя.

### `allOf` в d42

У d42 нет пересечения типов, поэтому `allOf` считается на уровне контракта и
распределяется по объединению. Самый частый случай — полиморфный DTO в стиле
springdoc, у которого одновременно `properties`, `oneOf` и `discriminator`:

```text
allOf(база, oneOf(V1, ..., Vn))  →  schema.any(база ∧ V1, ..., база ∧ Vn)
```

Перевод точный: значение проходит базу и хотя бы один вариант тогда и только
тогда, когда оно проходит хотя бы одну ветку. Эксклюзивность `oneOf` держит JSON
Schema — как у любого `oneOf`. `discriminator` сужает ветки своих вариантов (строка
таблицы ниже). JSON Schema контракта хранит `allOf` как есть.

| Пересечение | Результат |
| --- | --- |
| ветка равна своему варианту | ссылка на generated-схему варианта (`GeneratedConstantSchema`) |
| база объявляет свойство, которого нет у варианта | ветка — словарь со свойствами обоих |
| пустой открытый объект (`{type: object}`) ∧ объект | второй объект |
| объект ∧ объект | свойства объединяются, общие пересекаются, `required` — объединение; ключ, запрещённый `additionalProperties: false` одной стороны, выбрасывается (если он необязателен) или опустошает ветку |
| строка ∧ строка | `enum ∩ enum` в порядке более узкой стороны; `enum` фильтруется по `pattern` и длинам другой стороны; границы длины — строже |
| `integer` / `number` | границы строже, `enum ∩`; `multipleOf` у целых — НОК, у `number` — только равный |
| массив ∧ массив | `items` пересекаются, длины строже, `uniqueItems` — ИЛИ |
| `nullable` | остаётся, только если он у обеих сторон |
| ссылка на полиморфный DTO ∧ ссылка на его вариант | вариант |
| `allOf: [$ref база]` без своих ограничений | алиас базы (`GeneratedAndDtoSchema = GeneratedEdgePredicateDtoSchema`) |
| `discriminator` у объединения | в ветке варианта свойство обязательно, а из его `enum` исключены значения, которые `mapping` отдаёт другим вариантам; у строки без `enum` исключение не выражается |

Ветка, которая не допускает ни одного значения (`enum` варианта не пересекается
с `enum` базы), выбрасывается: это точно, но почти наверняка ошибка
спецификации, поэтому `geas update` называет её отдельной строкой. Недоказуемое
пересечение (два разных `pattern`, `integer` против `number`, ключ, который в
открытом объекте обязан отсутствовать, `allOf`, ссылающийся сам на себя) и
пересечение без единой непустой ветки не выражаются — см. следующий раздел;
причина называет ветку и contract path свойства.

Распределение идёт до отсечки цикла: рекурсия через вариант (`Or.args →
EdgePredicateV2Dto`) отсекается [общим механизмом](#рекурсия-в-d42).

### Конструкции, которые не выражаются в d42

Если конструкция точна в контракте и JSON Schema, но не выражается в d42
(`allOf` с недоказуемым или пустым пересечением, `multipleOf`, `minProperties`,
`pattern` вместе с границами длины), операция всё равно генерируется:

1. контракт и JSON Schema создаются как обычно;
2. d42-схемы не создаются для того направления, где встретилась конструкция;
   другое направление их сохраняет. Причина записывается в
   `contracts/<slug>.json`: `d42.<direction>_reason` и сводная `d42.reason`,
   модуль направления — `null`;
3. `geas update` печатает эту причину;
4. `OperationHandle.d42_schema()` для этого направления падает с той же причиной.

Моки и валидация продолжают работать через JSON Schema.

### Рекурсия в d42

Рекурсия d42 не отключает. Граф определений обходится в глубину от тел
направления (в порядке контракта), дальше свойства по имени и варианты
объединений по порядку. Ссылка, которая возвращает обход в определение с
текущего пути, становится узлом `RecursiveRefSchema`:

| Операция | Поведение отсечённого узла |
| --- | --- |
| валидация | по JSON Schema определения со всеми достижимыми `$defs`, без `format` (как у остального d42-пути) |
| `%` | делегируется типизированной схеме того же определения; частичная подстановка уходит вглубь |
| `fake()` / `build_fixture` | минимальный экземпляр, сверенный с JSON Schema; нет конечного значения — `RecursiveSchemaError` |
| `make_required()` | не затрагивается: он поверхностный |
| `overlay_generators` | путь до узла или сквозь него — `ContractOverlayError` |

JSON Schema отсечённых определений встраивается в d42-модуль
(`_RECURSION = RecursionContract({...})`), поэтому модуль самодостаточен.

## `format`

`format` проверяется при валидации. Поддержанные значения:

| `type` | Допустимые `format` |
| --- | --- |
| `string` | `binary`, `byte`, `date`, `date-time`, `duration`, `email`, `hostname`, `idn-email`, `idn-hostname`, `ipv4`, `ipv6`, `iri`, `iri-reference`, `json-pointer`, `password`, `regex`, `relative-json-pointer`, `time`, `uri`, `uri-reference`, `uuid` |
| `integer` | `int32`, `int64` |
| `number` | `float`, `double` |
| `boolean`, `object`, `array` | нет |

- `int32` и `int64` превращаются в явные границы `minimum`/`maximum`.
- `binary`, `byte` и `password` попадают в артефакт, но значение не проверяют.
- Неизвестный `format` по умолчанию отклоняется. Принять его можно двумя
  способами: `policies.unknown_formats: annotate` в manifest (для всего проекта)
  или waiver с правилом `allow_unknown_format` (для одной точки). В обоих случаях
  `format` сохраняется в артефакте и не проверяется.

## Параметры

| Расположение | Swagger 2.0 | OpenAPI 3.0 |
| --- | --- | --- |
| `path` | поддержано; обязан быть `required: true` | поддержано; обязан быть `required: true` |
| `query` | поддержано | поддержано |
| `header` | поддержано | поддержано |
| `cookie` | нет в спецификации | поддержано |
| `body` | поддержано, становится телом запроса | заменён на `requestBody` |
| `formData` | **отклоняется**: у тела формы нет JSON-контракта | — |
| параметр через `content` | — | отклоняется |
| параметр через `$ref` | поддержано | поддержано |
| параметры уровня Path Item | поддержано, объединяются по паре `(name, in)` | поддержано |

Параметр может быть только скаляром или массивом скаляров. Объекты, вложенные
массивы, массивы объектов и параметры со схемой через `$ref` на именованную
схему отклоняются.

Шаблон маршрута и объявленные path-параметры должны совпадать: переменная без
параметра или параметр без переменной отклоняются.

### Сериализация

Поддержаны только эти сочетания, все остальные отклоняются. Точечно разрешить
неподдержанное сочетание можно waiver'ом `allow_unsupported_serialization`,
тогда значение параметра не проверяется.

| `in` | `style` | `explode` | Форма значения |
| --- | --- | --- | --- |
| `path` | `simple` | `false` | скаляр; массив через запятую |
| `query` | `form` | `true` | скаляр; массив как повторяющийся ключ |
| `query` | `form` | `false` | скаляр; массив через запятую |
| `query` | `spaceDelimited` | `false` | массив через пробел |
| `query` | `pipeDelimited` | `false` | массив через `\|` |
| `header` | `simple` | `false` | скаляр; массив через запятую |
| `cookie` | `form` | `true` / `false` | скаляр |

Отклоняются также `deepObject`, `label`, `matrix` и `allowReserved`.

`collectionFormat` из Swagger 2.0 соответствует так: `csv` → `form`/`explode=false`,
`multi` → `form`/`explode=true`, `ssv` → `spaceDelimited`, `pipes` →
`pipeDelimited`; `tsv` отклоняется.

## Тела и ответы

| Конструкция | Поведение |
| --- | --- |
| `requestBody.content` (3.0) / `in: body` + `consumes` (2.0) | поддержано |
| несколько request content type | поддержано; один можно закрепить в manifest через `request.content_type` |
| `responses.<код>` | поддержано |
| `responses.default` | поддержано; в моке нужно явно передать числовой `status` |
| диапазоны кодов (`2XX`) | отклоняются |
| ответ без тела (204, пустой `default`) | поддержано, `schema: null` |
| несколько media type в одном ответе | поддержано |
| `application/json` и `<...>+json` | поддержано |
| `application/json;charset=UTF-8` | поддержано: параметры отбрасываются, регистр нормализуется |
| `*/*` в Swagger 2.0 | считается JSON |
| не-JSON media type (`application/pdf`, `text/plain`, …) | вариант записывается в артефакт с причиной, контракт тела не строится; операция генерируется |
| заголовки ответа | поддержаны, включая `$ref` и пустой `headers: {}` |

## `$ref`

| Вид ссылки | Поведение |
| --- | --- |
| локальная в том же файле | поддержано |
| межфайловая внутри корня источника | поддержано; корень — каталог спецификации или `sources.<name>.root` |
| межфайловая за пределами корня | **отклоняется** |
| через symlink, ведущий за корень | **отклоняется** |
| `http(s)://` | **отклоняется всегда**: geas не ходит в сеть |
| `$ref` рядом с `description`/`title`/`example`/`summary` | принимается, соседние ключи отбрасываются |
| `$ref` рядом с `readOnly`/`writeOnly`/`nullable` (`x-nullable`) | принимается, соседние ключи **применяются** |
| `$ref` рядом с любым другим ключом | **отклоняется**: OpenAPI 3.0 такие ключи игнорирует, и контракт отличался бы от того, что написано |
| цепочки ссылок | поддержаны |
| рекурсия (прямая и взаимная) | контракт и JSON Schema строятся; d42-схемы создаются с отсечкой цикла (см. [«Рекурсия в d42»](#рекурсия-в-d42)) |
| больше 256 файлов в одном источнике | отклоняется: вероятно, цикл или слишком широкий `root` |
